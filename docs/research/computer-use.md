# Computer use для Jcode: нативный AX и GUI-агент для сервера

21 ноября 2026. Сравнение основано на исходниках и неизменяющем замере истории. GUI, TCC, daemon и сборки не трогались. Обещания чужих README о совместимости обозначены как контракт или заявленное поведение, не как наша проверка. [Решения владельца и план v2](#решения-владельца-и-план-v2) уточняют первые рекомендации по упаковке, разрешениям и фоновому вводу.

## Вывод

Сделать основной путь **оконным и AX-first**, с коротким `observe → act → verify` и отдельным pixel fallback. В macOS одни и те же операции должны идти в нативный broker в GUI-сессии пользователя, независимо от того, кто инициировал вызов: TUI, Desktop или аутентифицированный `jcode serve`. Прямая работа со всем экраном не входит в обычный фоновый режим. Не переключаться на неё автоматически. Без вошедшего GUI-пользователя возвращать `no_gui_session`. Для безнадзорных задач, которым нужно больше, запускать отдельный GUI-аккаунт или VM, не обещать «AX без WindowServer».

Первый кандидат для AX: небольшие компоненты macOS sidecar Orca, не весь Orca runtime. У OMP взять более строгие правила идентичности цели, верификации и отказа до доставки. Для фонового ввода взять открытый аналог маршрута Codex из Cua Driver. Оставить точные проверки совместимости в [плане v2](#решения-владельца-и-план-v2).

### Что важно в реализациях

**OMP.** `packages/coding-agent/src/tools/computer/{prelude.js,prelude.py,supervisor.ts,worker.ts,protocol.ts}` дают инструмент как скриптуемую сессию: список дисплеев, окон, приложений, захват и input по связанному с последним кадром target, AX-поиск и actions, меню, clipboard, несколько операций за вызов. `crates/natives/src/desktop/{ax.rs,frame.rs,control.rs}` связывают живые ссылки, перепроверяют роль/метку и срок жизни, отказывают при смене кадровых размеров. Ссылка переживает пропуск в одном AX snapshot, но macOS stale ref отказывает и до истечения, если элемент исчез или поменял идентичность. Исключение для единственной доказуемо совпавшей строки таблицы не нужно переносить на первом этапе. `macos/{ax.rs,input.rs,route.rs,skylight.rs,window_order.rs,permission.rs,capture.rs}` смешивают публичные и приватные платформенные способы для фоновых clicks/keys, защиты фокуса и capture. Отказ до ввода отделён от partial delivery / `AxUnconfirmed`; повтор последнего небезопасен. Собственные подтверждения для takeover/control и режим `backgroundFallback: refuse` полезны, но обычный default `takeover` для Jcode не подходит. `read_only` ограничивает методы facade, не произвольный host JS. Нет установленного отдельного GUI broker для произвольного daemon/SSH; нужна достижимая GUI-сессия. На Linux Wayland backend явно не обещает background per-window input; X11 и Windows имеют другие ограничения.

**Orca.** Swift `native/computer-use-macos/Sources/OrcaComputerUseMacOS/main.swift` защищает маршрутизацию по PID/окну, читает настоящие AX-элементы, строит снимок, исполняет семантику или synthetic input и возвращает новый state и verification. `OrcaComputerUseMacOSCore/{AccessibilityWindowIdentity,StableElementIndexes,SnapshotRendering,ComputerSnapshotCachePolicy,BackgroundInputTransport,KeyboardInputSafety}.swift` отделяют полезные примитивы. `src/main/computer/computer-snapshot-tree-diff.ts` и CLI помогают не повторять неизменные ветви. Стабильность индекса в новых снимках не является публичным вечным handle. `enabled` actions и проверка set-value предпочтительнее «мышь отправлена», которая лишь `unverified`. Есть отказы для всплывающих списков, input в hidden/minimized и ряда приложений. `main.swift` проверяет AX, capture, ожидает оседание TCC и открывает setup UI; sidecar ожидает токен и проверяет peer, app identity и владение сессией; `macos-native-provider-{transport,socket,paths}.ts` связывают это с Orca. Native CLI не подменяет policy согласия: skill сам требует не делать необратимое без запроса, `--restore-window` не является криптографическим approval. Наличие Unix IPC само по себе не доказывает работу ни после logout, ни из любого SSH bootstrap. Linux/Windows runtime существуют, но не служат источником macOS-обещаний.

**Codex.** По Rust-исходникам видны включение feature, macOS/Windows requirements/config и MCP-политика подтверждений для trusted connector. Локальная `.mcp.json` у `unified-computer-use` маршрутизирует REPL, в поставке `@oai/sky` отдельно имеет JS client/service и macOS `SkyComputerUseService`. Mac skill советует AX diff и явно выводить image только при необходимости; в API документации `screenshot.url` общий, поставляемый skill описывает `file://`. Индексы из последнего состояния и координаты окна не являются обещанием, что stale адрес всегда отвергается. Не выводим из двоичного файла, какие вызовы AX/CG/SkyLight он использует и как сохраняет фокус. [Инструкция OpenAI](https://developers.openai.com/training/walkthroughs/using-your-computer-and-browser) требует Accessibility и Screen Recording на macOS; точная TCC identity и необходимость Automation не установлены. Workspace app controls подтверждены в [OpenAI Admin Guide](https://help.openai.com/en/articles/20001510-manage-browser-and-computer-use-in-your-enterprise-workspace). [Locked mode для допустимых аккаунтов](https://help.openai.com/en/articles/6825453-how-do-i-use-chatgpt-with-browsing) не доказывает работу после logout. [Релиз OpenAI](https://openai.com/index/codex-for-almost-everything/) описывает компьютер как возможность Desktop; флаг в OSS CLI не равен работающему native backend. Код и лицензию native service на GitHub не нашли; доступные интерфейс, packaging и политики достаточны, чтобы сравнить UX, но не чтобы переносить реализацию.

**Pi Rust.** `src/computer.rs` задаёт компактный enum и происхождение решений об approval: model fields не могут его подделать, в отсутствии picker default deny для мутаций. `native/macos.swift` делает AX read, фильтрует secure text, предварительно проверяет AX и capture. `native/macos_input.swift` держит lease, делает checkpoints и освобождает input; `native/macos.rs` проверяет receipt и image target. AX дерево не является API семантических мутаций. Нет GUI-sidecar в самостоятельном login lifecycle. Read-only capture/clipboard могут раскрываться модели без отдельного approval, `authorize` выводит args в окно picker при мутации, что не следует копировать. В Linux fallback native AT-SPI зависит от текущего desktop bus. Не переносить даже небольшие куски под Rider: идеи подтверждения у доверенного host и проверки receipt можно реализовать независимо.

## Jcode сегодня

`crates/jcode-app-core/src/tool/computer/mod.rs` запускает `dispatch` в `spawn_blocking`. Группы: `discover/setup/check_permissions`; `ui/find_element/element_at/press/get_value/set_value/perform_action/select_menu`; `screenshot/window_screenshot/ocr`; pointer, scroll, type, key и отдельные key down/up; список и управление окнами/приложениями; clipboard; AppleScript/JXA; `wait_for/notify/system_state/set_brightness`. Список доступен в `discover.rs`. `cap_output` режет текст по **16 000 байтам** до UTF-8 boundary, после того как бэкенд уже прочитал и развернул его. В `mod.rs` default depth **12**. Это константы исходников, не измеренный бюджет модели.

* **AX и Automation.** `ax.rs` и большая часть `win.rs` ходят через `/usr/bin/osascript` в System Events. Для работы нужны AX и применимое согласие Apple Events к System Events; `activate_app`/`quit_app` и произвольные scripts могут затрагивать другие Automation targets. Фоновые `AXPress`/`AXValue` не двигают физический указатель, но нет точного `window_ref`, проверки, что ребёнок ещё тот же, или обязательного readback. Смена front window или reorder детей превращают валидный `[int]` в другой элемент. Меню явно выставляет `frontmost`; управление окном тоже сфокусировано на front window. `osa.rs` классифицирует часть ошибок TCC, но широкие текстовые шаблоны не заменяют preflight конкретного API и точного адресата.
* **Input.** `input.rs` постит CoreGraphics events в общий tap. Координатный клик/скролл двигают реальный курсор; Unicode и chord доставляются текущему focus, независимо от предыдущего `app` и снимка. Вызов «отправлено» не равен результату. Раздельные key down/up и независимые `spawn_blocking` не дают общего lease, guaranteed release и арбитража между агентами на desktop.
* **Capture/OCR.** `screen.rs` зовёт `screencapture`, пользуется Screen Recording, делает временные файлы и отправляет image block после fit; OCR требует Swift/Vision (предусмотрен резерв), возвращает текст с bounds. Screen capture и window state читаются в разные вызовы, ID кадра или привязки pixel → конкретное окно нет. `window_screenshot` сообщает размер, но не самодостаточное отображение пикселей в screen points. `list_windows` через CoreGraphics JXA не требует Apple Events сам по себе, но набор видимых заголовков ограничен системой разрешений.
* **TCC.** `setup.rs` считает AX через System Events и Screen Recording через пробную запись изображения, а не через отдельные `AXIsProcessTrusted` и `CGPreflightScreenCaptureAccess` у конечного исполнителя. `check_permissions` может инициировать TCC взаимодействие, Automation не отделена от Accessibility. `setup` открывает System Settings и опрашивает AX до **30 с** (исходник), при этом не гарантирует грант нужной identity. `dry_run` для mutating allowlist лишь возвращает имя verb, не проверяет цель; `setup` в этот allowlist не входит. Tool не имеет своей trust policy, app scope или протокола подтверждения. Arbitrary script и clipboard дают более широкий доступ, чем оконный AX.
* **TUI, daemon, Desktop.** `server/socket.rs::spawn_server_notify` запускает сервер с `setsid`, что отвязывает POSIX terminal, но не выбирает Aqua-сеанс и не создаёт WindowServer. При GUI-старте доступ зависит от GUI bootstrap, WindowServer и ответственной TCC identity конкретной цепочки; `setsid` сам по себе не доказывает ни успех, ни отказ. Desktop `crates/jcode-desktop-harness/src/{harness,platform}.rs` подключает SDK к harness API/shared daemon, а не проксирует настоящий AX в окно Desktop. Грант только `Jcode.app` нельзя считать достаточным для daemon, запущенного другим способом. В `computer/` нет выбора logged-in user, broker, ошибки `no_gui_session`, server/client routing или отдельного безопасного remote policy. Обычный SSH-клиент может говорить с уже запущенным GUI-host при явной авторизации; запуск самого инструмента из SSH, LaunchDaemon или до login не имеет гарантированного GUI/TCC. На Linux native tool отказывает.
* **Приватность.** `agent/tools.rs::tool_output_to_content_blocks` сохраняет tool result и отдельный image block, а `jcode-base/src/session.rs::decay_old_tool_images` описывает decay в истории. AX/OCR/clipboard могут содержать чувствительные данные, нет редактирования по приложению или полям в этом tool. Ожидание в `sys.rs` не отличает разрешение/поломку AX от ненаступившего условия. Нужны типизированные причины, secure field redaction, план хранения, ограничение capture области и запрет background→foreground replay.

## Первоначальный контракт и доноры

Этот раздел сохраняет исходные технические предложения. При расхождении действуют решения v2, в частности по GUI broker, согласиям и отбору доноров.

Один нативный инструмент модели `computer` (сохранить старый tool на время обратимой миграции). Discriminated union по `op`, а не общий мешок nullable params. Начать с `capabilities`, `list_apps`, `list_windows`, `observe`, `act`, `wait`. `act` принимает типизированный verb и ровно один target: `element_ref`, `window_ref`, `frame_point`. Для сложных действий `menu_path`, `select_text`, `set_value`, `text`, `key_chord`, `scroll` и `drag` задать свои типы, а не произвольный AppleScript. Редкие возможности раскрывать через `discover`; не давать script как обход gate. Функциональность дополнять scoped clipboard, окно/app lifecycle, dialogs/sheets, OCR и явным pointer fallback. Пакет действий после одиночных операций, только с промежуточным predicate, отменой и без неявного повтора мутаций.

```text
observe(window_ref, view=ax|image|ocr|ax_image, query?, since?, budget?)
  -> {target, snapshot_id, base_id?, focus_ref?, tree_or_patch?, omitted?, frame?, warnings}
act(target, verb, input, expect?)
  -> {delivery: not_sent|sent|partial|unknown, effect: verified|unverified,
      reason?, next_state?}
wait(window_ref, predicate, deadline)
  -> {matched, next_state?, reason?}
```

* **Состояние.** По умолчанию AX точного окна, включая sheet/focus и advertised actions; компактные строки role/label/value summary/ref. Дефолтный фильтр оставляет полезные элементы, query сохраняет предков; явные `truncated` и продолжение для большого дерева. При token budget гарантировать предупреждения и контекст редактирования вместо молчаливой отсечки. `since` привязан к `base_id`, после reconnect/compaction запрашивается полный state. Image и OCR только опцией, window crop/zoom, `frame_id` со scale/bounds; любое coordinate action проверяет кадр и WindowServer геометрию. Не посылать base64 в текст. Для replay старые images заменять безопасными receipts согласно принятой retention policy.
* **Идентичность.** Broker хранит AXUIElement, `snapshot_id`, scope (GUI user/session, broker generation, tool session, PID + process generation, window identity). Для модели короткие непрозрачные refs и никаких физических AX индексов. Перепроверять live membership, `role/subrole` и устойчивый идентификатор/label, enabled и ожидаемую область; для сменившейся роли, закрытого окна, процессов после restart, дубликата или ожидания после более старого кадра вернуть `stale_ref` и свежий snapshot. Не искать «похожий» контрол по тому же порядковому номеру. Diff не должен повышать срок жизни handle.
* **Доставка.** AX `press`, `set_value`/`selectedText`, семантическое меню и `perform` по объявленному action first. На форму/кнопку эффект подтверждает readback или `expect`; без признака результата `unverified`. Для приложений без нужного AX: условный app-targeted input лишь после тестов. Без него отказывать `background_unavailable` до отправки; foreground только явно разрешённый lease, оператор видит app/окно и риск. Secure prompts, password fields и непроверенный диалог не автоматизировать. Падение/прерывание освобождает удержанные клавиши, и не запускает повтор даже при потерянном ответе. `AXObserver` на app/window + ограниченный polling fallback для неподдерживаемых нотификаций; см. [AXObserverCreate](https://developer.apple.com/documentation/applicationservices/1460133-axobservercreate). Predicate ограничить `exists`, `value_changed`, `focused`, `window_opened/closed`, без произвольного кода.
* **Сервер.** Подписанный macOS GUI agent с устойчивым bundle ID / designated requirement, отдельный от TUI, Desktop и их self-reload. В GUI login domain через `SMAppService`/LaunchAgent при явном setup. Agent держит исходящие аутентифицированные локальные подключения к daemon или слушает per-user socket с локальной аутентификацией (конкретный выбор по probe bootstrap). UID проверять вместе с peer/process identity и scope, а не полагаться лишь на «тот же UID». Без TCP listener, credentials не в tool inputs, не в argv/логах. Broker получает ограниченный manifest с app/операциями на конкретную сессию; daemon не выдаёт network credentials как право на экран. Один broker на GUI-сеанс, запись сериализуется на уровне desktop, read state не открывает канал для поздней мутации без проверки. Idle/reload/reconnect и policy revoke инвалидируют lease. Для SSH командный клиент вызывает daemon по уже авторизованному каналу, а агент должен быть отдельно активен в нужном logged-in GUI; не выбирать активного пользователя за клиента. `no_gui_session`, `locked`, `wrong_gui_user` и `broker_unavailable` не маскировать под отсутствие TCC, приложение не переключать автоматически. Состояния lock и fast user switching проверить отдельно.
* **TCC и согласие.** `capabilities` получает независимые статусы GUI, AX для исполнителя через [AXIsProcessTrustedWithOptions](https://developer.apple.com/documentation/applicationservices/1459186-axisprocesstrustedwithoptions), [Screen Recording](https://support.apple.com/guide/mac-help/mchld6aa7d23/mac) через preflight и точную identity, Automation только на отдельном legacy route по реально нужной паре приложений, см. [Apple: Automation](https://support.apple.com/guide/mac-help/mchl07817563/mac). Read-only preflight без диалога/захвата. Prompt или переход в Settings инициирует пользователь явным setup локально. Не расширять до Input Monitoring автоматически: если отдельный guard требует его, объявлять как отдельную capability и спорный opt-in. Доступность наблюдения не означает согласия на отправку/покупку/удаление. Ввести scoped read/mutation/foreground consent отдельно для local и server; запрет system auth UI, lock screen, иных пользователей и выгрузки скриншотов в нерелевантные контексты. Экранный текст и OCR не дают агенту новых инструкций. В audit писать только operation class/delivery/политику, не values/screenshots.

## Решения владельца и план v2

Уточнения на 21 ноября 2026 года заменяют прежние рекомендации о helper, согласиях и сроках. SSH на тот же Mac обращается к уже работающему GUI-процессу того же пользователя. При установке пользователь один раз выдаёт Accessibility и Screen Recording стабильной подписанной identity. При первом обращении к `computer` за сессию локальный доверенный интерфейс показывает **один** запрос с приложениями, операциями, возможной передачей изображения провайдеру и режимом ввода. Последующие действия внутри согласованного scope не спрашивают снова. Действие вне scope, системная аутентификация и операции, для которых провайдер требует дополнительного подтверждения, в v1 возвращают управление человеку вместо второго запроса. Разрешение macOS, даже уже выданное, не заменяет это согласие. Лицензия не фильтрует кандидатов на заимствование. Для взятого кода сохраняем provenance и notices, а недоступный исходник не считаем готовым донором.

### Быстрый выбор поверх AX, пиксельные агенты отдельно

Под «system one типа jev» имеется в виду **Jev от TypeSafe AI**. У Jcode уже есть рабочая архитектурная точка входа: [`browser(action="handoff")`](../browser-task-handoff.md), `browser_fast.rs` и `browser_jev.rs` строят меню действий из текущего состояния, Jev возвращает ID, Jcode исполняет и перепроверяет. `jcode-base::jev` уже умеет подписочный Jcode, TypeSafe, OpenRouter и AIMLAPI. Приоритет подписки в `auto` и проверка entitlement не разрешают тихо переключаться на платный BYOK при отказе. Laya есть как явный отдельный выбор. Это сведения из исходников на `6bbcc7485`, не новый end-to-end запрос. Для desktop нужен тот же цикл, но с AX refs и prebound аргументами вместо DOM. Переиспользовать клиент Jev, а не привязывать desktop к браузерному runtime.

[Архивный Jcode browser тест](../browser-handoff-speed-20260921.md) дал 4 против 11 parent tool calls во всех трёх парах, медиану парных ускорений 1.685× на одной задаче. Более новый сентябрьский прогон остановился на 402. Ни одно число не переносится на desktop. Сравнительной точности на одном workload у нас нет.

Решение: **AX-first с обычным tool по умолчанию**, затем opt-in быстрый chooser поверх AX для повторяемых маршрутов. Для chooser сформировать допустимые действия локально, привязать варианты к `snapshot_id`, повторно проверить цель после ответа и до доставки. Рискованные действия отсекает policy, а не confidence модели. Сначала Jev, потом Luna Decisions по тому же тесту. Pixel tool OpenAI прогнать первым на изолированном display, Luna как бюджетный кандидат и Terra как кандидат на качество. Anthropic и Gemini сравнивать после доказательства пользы pixel-ветки, не писать три транспорта заранее. Чужие опубликованные desktop benchmarks не заменяют сравнение в Jcode.

### Фоновый ввод и владелец разрешений на Mac

**Что делает Codex.** Открытый CLI подключает plugin, поставка `unified-computer-use` `26.1103.41825` объявляет REPL, а `@oai/sky` адресует приложение и окно отдельному `SkyComputerUseService`. У локального service build `1001824` signing identifier `com.openai.sky.CUAService`, у bundled клиента `com.openai.sky.CUAService.cli`. Проверены `codesign -d -r-` и `nm -um` без запуска: сервис импортирует AX read/perform/set и ScreenCaptureKit. Это подтверждает используемые платформенные библиотеки и разделение процессов. Нет статических импортов, подтверждающих конкретный private input path. [Публичный отчёт о клавиатуре](https://github.com/openai/codex/issues/53861) наблюдал per-process event taps на другой сборке, но не устанавливает транспорт кликов или порядок работы Sky. Не копировать API или поведение, которого нельзя подтвердить. Не зависеть от установки Codex или его бинарного service.

**Что взять.** Совместимость с Codex означает окно и ввод в фоне, пока пользователь работает в другом приложении, а не точную копию закрытого бинарника. Донор фонового маршрута: [Cua Driver на `b18edec`](https://github.com/trycua/cua/tree/b18edec39d0122fb3264df0513b9ee78e01a4f35/libs/cua-driver/rust/crates/platform-macos/src). Точки входа `input/{mouse,keyboard,skylight}.rs`, `focus_guard.rs` и `key_focus_guard.rs`. [Описание автора](https://github.com/trycua/cua/blob/main/blog/inside-macos-window-internals.md) объясняет window focus без поднятия, PID-адресную доставку через SkyLight и границы публичного `CGEventPostToPid`. [Его матрица](https://github.com/trycua/cua/blob/main/libs/cua-driver/docs/action-support.md) фиксирует приложения и операции, для которых фон недоступен. Взять минимальный транспорт и тестовые сценарии, оставить AX и readback первыми. Не копировать ветки `input/mouse.rs`, которые ещё отправляют один event через два транспорта. Для Jcode один способ доставки на операцию. Если результат неясен, вернуть `unknown` без повтора или HID. На своём Mac не активировать чужое окно для имитации background. Начинать с клика, текста и простого chord, отдельно маркировать неподдержанные меню и drag. Технические доказательства до включения: fixture AppKit, Chromium/Electron и WebKit, фоновые два окна одного процесса, отдельный sentinel ввода и фокуса, отсутствие подмены клавиш или сдвига указателя. Изменение поведения на новой версии macOS отключает неподтверждённый маршрут.

**Кто получает TCC.** Для v1 предложен сам запущенный **Jcode Desktop**, если проверка подтвердит стабильную подпись и native AX/capture/input именно внутри него. Не делегировать их бинарнику `jcode` или `osascript`, даже если Desktop вызвал его. Desktop становится локальным GUI broker. TUI и SSH-клиент разговаривают с daemon, daemon с Desktop через аутентифицированный per-user IPC. IPC не публикуется в сеть. Отдельный пользователь, lock и logout не получают чужой сессии. При остановленном Desktop вернуть `broker_unavailable`, а не пытаться создать GUI через SSH. `no_gui_session` означает, что нет GUI-сеанса. На `origin/main` Desktop `dbc14d16` есть упаковка `scripts/package-macos.sh`, stable bundle identity через `packaging/macos/Info.plist.in`, обычный harness-клиент, но нет проверенного GUI broker; показанный entitlements-файл не выдаёт TCC. [Apple TN3127](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements/) объясняет designated requirement, которым macOS узнаёт обновлённый код. Не обещать сохранение гранта у ad hoc сборок или при смене Team ID. Проверка должна включать обновление двух подписанных сборок поверх существующего grant и явный отказ после revoke без запроса из headless daemon.

Подписанный helper нужен, только если принимаем работу при закрытом Desktop, standalone CLI install без Desktop, либо Desktop не может исполнять проверенный backend или нужен отдельный crash domain. Тогда это отдельный устойчивый app/login agent, а не root daemon. На обычное автоматическое наследование TCC не рассчитывать. Определить конечную identity до установки. Миграция identity после Desktop MVP может потребовать нового OS grant, поэтому её нельзя обещать как незаметное обновление. Настройка не обходит системные prompts и не меняет TCC напрямую.

### Linux и облачный remote

[`cloudflare/computer`](https://github.com/cloudflare/computer) на просмотренном `cd0146b` даёт `Workspace` внутри Durable Object, виртуальные файлы в SQLite и `workspace.runtime` с выбираемыми исполнителями, включая Linux container. Это не образ GUI, не VNC, не macOS broker и не OpenAI `computer` tool. Можно хостить там Linux GUI в собственном образе после qualification lifecycle, start/stop, private ingress и раздельных профилей. Не ставить это в критический путь v1. [Cloudflare Browser Run](https://developers.cloudflare.com/browser-run/) даёт отдельный hosted browser, а не доступ к произвольному Linux или Mac окну. Существующий Jcode `cloud_environment` управляет файлами, окружением и допущенными credentials, не выдаёт разрешения на экран и не должен переносить профили с Mac.

Для первого удалённого Linux-образа взять **отдельный X11 display на каждую аренду**: [Xvfb](https://www.x.org/releases/X11R7.6/doc/man/man1/Xvfb.1.xhtml), лёгкий оконный менеджер и session D-Bus. [AT-SPI](https://docs.gtk.org/atspi2/) даёт дерево, роли, свойства, actions и события для поддерживаемых GTK/Qt/Chromium приложений. Прочитать сначала AT-SPI, для недостающего контрола взять кадр выделенного display и X11 input. Это позволяет работать параллельно человеку на другом display, а не обещает точный фоновый ввод в любом скрытом X11-окне. [TigerVNC Xvnc](https://tigervnc.org/doc/Xvnc.html) заменяет Xvfb, если нужен удалённый визуальный просмотр и ручной takeover. VNC только по аутентифицированному частному каналу, без публичного порта. Tool и VNC должны брать одну аренду записи. Не пробрасывать X socket, D-Bus или профили хоста. Изоляция по UID/container или VM, приватный endpoint, ограничения egress, временные профили и уничтожение по TTL. Wayland и чужой пользовательский desktop не входят в первую поставку.

### Браузер Social Research Hub

За «агентским браузером» в локальном SRH стоит **Obscura**, самостоятельный headless движок с V8 и реализацией части CDP, не Playwright с патчем Chromium и не `agent-chrome` на 9333. Пин SRH `b5f284e`: `deploy/obscura.Dockerfile` берёт проверяемый релиз Obscura `v0.2.6`, upstream `8534b401`. `deploy/compose.yaml` и `browser-entrypoint.sh` запускают отдельные Linux sidecars и профили. `hub-browser` собирает provider registry, проверку сессий и factory, `hub-accounts/src/browser/{operations,…}` отвечает за CDP, scoped reads и lifecycle. Hub использует Chromium CDP как отдельный вариант подключения. OMP вызывает типизированные Hub MCP tools, а не общий CDP. Его `clients/omp/modern-http.patch` правит stateless MCP HTTP клиента, не браузерный движок.

Незакоммиченный checkout SRH заменяет бинарный релиз на native amd64/arm64 source build с SHA-256 исходника и патчей, `patch --fuzz=0` и отдельными regression stages. Пять производственных патч-файлов в `deploy/obscura-patches`: `posted-task-recovery` исправляет планирование очереди JS, `fetch-session-ownership` связывает CDP Fetch с владельцем сессии, `classic-script-interception` охватывает классические script requests, `waapi-color` включает исправления анимаций цвета/easing, `request-document-identity` сохраняет принадлежность запросов к документу. Дополнительные тестовые патчи не входят в production builder. В текущем entrypoint есть opt-in альтернативных настроек движка для одного профиля. Их не переносить в общий браузерный инструмент. Эти изменения просмотрены read-only. Их наличие в локальном diff не доказывает ни публикацию, ни развёртывание образа.

Из истории OMP использованы только агрегаты: просмотрены первые записи 935 кандидатов JSONL в `~/.omp/agent/{sessions,custom-session-files}`, совпадений с точным каноническим `cwd` SRH не найдено. Содержимое чужих сессий не читалось и не выгружалось. Эфемерные журналы smoke удаляются, как описано в `docs/omp-client.md`. Сохранённый там итог: изолированный bundled TUI прошёл 4 modern и 5 legacy запросов, 2 локальных SSE-раунда; production TUI увидел 37 Hub tools и завершил один HN read с `committed`. HN не использует Obscura. `docs/implementation-ledger.md` отдельно фиксирует успешные изолированные CDP cleanup fixtures и неуспешный NAS X прогон с истёкшим сроком и нулём результатов. Это не доказательство паритета с Chromium, универсального Browser API или готовности текущего грязного пина. Новых OMP сессий, сетевых действий от аккаунтов и запусков движка не было.

Решение для Linux VPS: **headless Chromium + Playwright/CDP по умолчанию**, без Xvfb для браузерных задач. Нативный агентский инструмент нужен, но не новый верхнеуровневый `cdp` или обёртка raw `eval`: добавить backend к уже существующему Jcode `browser`. Снаружи остаются scoped tabs, DOM/AX snapshot и bounded actions. Профили SRH, auth capture, токены, CDP endpoint и API чтения аккаунтов не переезжают. Chromium и Obscura сравнить на одной локальной browser fixture по навигации, frame, DOM, click/type, загрузкам, восстановлению и изоляции. Obscura оставить opt-in только если докажет совместимость для нужных задач и меньшие реальные RSS/старт/стоимость. Упаковку версии движка и его regression image можно выделить в отдельный OCI-пакет после появления второго потребителя. Не выделять `hub-browser` с провайдерной логикой, не форкать его в Jcode и не делать отдельный Rust crate ради одного пробного backend.

### Лейны реализации и приёмка

Названия новых файлов предварительные, границы владения обязательные. Каждый лейн даёт runnable fixture с первым красным тестом, затем зелёную проверку. Координатор владеет workspace manifests, реестрами `tool/mod.rs`, daemon entrypoint и merge. Параллельные агенты работают в отдельных worktree, Desktop и `jcode` лежат соседями. `JUSTRUST_SLOTS=2`, scoped test и clippy по изменённым Rust crates. Никакого общего daemon или daily-driver app в тестах.

Fake backend доказывает одинаковый контракт CLI и daemon | Старт. Сначала зафиксировать wire, fixture и typed receipts |

Для eval заранее заморозить версии, окно, масштаб и начальное состояние. Для каждой задачи чередовать порядок сравниваемых путей. В долю успехов включить все начатые попытки, включая отказы, таймауты и недоставленные действия. Успешными считать только полные попытки с независимо подтверждённым результатом. Отдельные счётчики: число model requests и физических действий, точность цели, доля задач с подтверждённым финалом, вмешательства в фокус, p50/p90 времени, input/cached/output/vision usage и стоимость на успешную задачу. Фиксировать неверные действия отдельно от отказов. Первой поставкой считать A+B+D после runtime-приёмки на подписанной тестовой установке, C подключать только для прошедших сочетаний. F можно выпускать независимо, E и G не блокируют Mac AX. Здесь проверены исходники, пины, статические метаданные и сохранённые агрегаты, а не живой GUI, TCC, VPS или API провайдеров.
