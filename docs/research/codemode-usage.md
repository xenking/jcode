# Code Mode в Jcode: где ещё есть экономия

Рекомендация на 21 ноября 2026. Сначала сократить длинные ответы `codemode`, затем помочь агенту исправлять ошибки вложенных вызовов. За неделю агент использовал инструмент 955 раз, обычно для четырёх вложенных вызовов. Данных в пользу нового рантайма или обязательного Code Mode нет.

## Что делают другие harness

| Harness и версия | Контракт модели и как она выбирает инструмент | Результат, ошибки, состояние и ограничения |
| --- | --- | --- |
| **Jcode**, исследование реализации на `a0bfe7a95` | `{code, intent}`, тело async-функции в новом QuickJS VM. JS и TS без typecheck. `tools.<name>`, `callTool`, `listTools`, `types` и `describeTool` видят инструменты сессии. Декларации только на запрос и только для входов. Системный [Tool calls](../../crates/jcode-base/src/prompt.rs#L47-L56) предлагает 5+ вызовов, зависимости, циклы по результату, фильтрацию; оставляет `batch` для независимого verbatim и `bash` для shell. | [Host](../../crates/jcode-app-core/src/tool/codemode.rs#L58-L80) использует обычный Registry с политиками и hooks. Скрипт получает строку либо распарсенные JSON-объект/массив, не обещанный тип результата. Наружу идут `return`, консоль, ошибки и квитанции. [Лимиты](../CODEMODE.md#limits): 64 MiB heap, 1 MiB stack, 300 с wall clock, 2 000 вложенных вызовов, 64 KiB логов и 60 000 символов отчёта со spill. JSON-store на сессию, не REPL. После ошибки частичные вызовы не откатываются. |
| **Pi (TypeScript)**, [исходник инструмента][pi-tool], [исполнитель][pi-exec] на `780bf31` | Явно включаемое расширение. Raw JS там, где провайдер поддерживает грамматику, async body в QuickJS/Wasm. `on` оставляет обычные инструменты напрямую, `only` прячет их за Code Mode. Предел деклараций в описании 3 000 оценочных токенов, deferred MCP не переписывает статическое описание. `ALL_TOOLS`, BM25 `searchTools`, `describeTool` и `describeNamespace`. Для прямых инструментов в режиме `on` показывает, как вызвать их из скрипта и что вернётся. В системном промпте буквально рекомендует независимые вызовы через `Promise.allSettled`, цепочки и фильтрацию. | [Контракт][pi-doc]: типизированный `structuredContent`, если инструмент объявил выходную схему; у MCP нативный `CallToolResult`. Обычный отказ бросает `Error`; общий сбой сохраняет частичный вывод. `text`/`image`/`return`/console, без host FS, сети и таймеров. Бюджет `max_output_tokens` (10 000 по умолчанию) с head/tail и полным артефактом, `timeout_ms` опционален. Heap 256 MiB, два worker-слота по умолчанию. JSON-записи сохраняются в ветке сессии только при успехе, до 262 144 символов на значение и 1 048 576 суммарно. |
| **Сторонний харнесс с `eval`** | Схема `{language: py\|js, code, title?, timeout?, reset?}`, отключённый backend исчезает из объявления. Python subprocess с top-level `await`; JS/TS в Bun VM, доступ к Bun, FS, сети и импорту. `tool.<name>(args)`, список имён сессии и расширенные guides через внутренние URI-ресурсы, а не копия всех типовых сигнатур. Модельное описание говорит не повторять успешную настройку и исправлять только сбойную ячейку; отдельные промпт-секции для активных preludes. Документация советует `eval` вместо `python -c`/`node -e` для разового кода. | Живые переменные отдельно по языкам, через compaction в том же процессе, но не после рестарта; потерю состояния объявляет. Потоковый stdout/stderr и вложения, ошибка/exit code в деталях, длинный вывод доступен как `local://`-артефакт. Структурированный MCP доступен через `details.structuredContent`. 30 с по умолчанию, `0` отключает watchdog, ненулевой ограничен политикой 1–3 600 с и `tools.maxTimeout`; часть host waits ставит watchdog на паузу. Это интерактивная ячейка, а не эквивалент изоляции Jcode. |
| **Pi Agent Rust**, [`EvalTool`][pir-tool], [bridge][pir-bridge] на `b217af5` | Opt-in `eval`, выделенный поток с постоянным QuickJS realm или постоянный Python subprocess. Описание подсказывает вызывать инструменты по обычным имёнам через `tool.<name>` и явно различает текстовый вызов и `tool.result(name, args)`. Расширенный bridge для subagents и batch judgment; в проверенных исходниках нет аналога `types()` для списка деклараций или отдельного общего правила «выбирай после N вызовов». | `tool.result` возвращает нативные content/details/isError. Богатый вывод через `display`, сбои имеют коды `EVAL_*`; отмена/жёсткий timeout могут сбросить kernel, об этом сообщается. Ячейка по умолчанию 30 с, диапазон 1–600 с; Python soft timeout опционально пытается сохранить переменные. Транспорт и rich output имеют отдельные пределы (16 MiB кадр, 2/4 MiB на один/все display items). |
| **Codex CLI**, [план выдачи][codex-plan], [модельное описание][codex-desc] на `2fb728d` | `exec` принимает raw JS в V8. `CodeMode`/`CodeModeOnly` выбираются средой и моделью. Steering в исследованном пути прежде всего через выдачу/скрытие прямых инструментов и описание `exec`, а не фиксированное число вызовов в общем системном промпте. `ALL_TOOLS`, typed declarations, `tools.tool_search` с BM25 для deferred, включая типы MCP-результата. | `text`/изображения, результат вложенного инструмента как объект или строка по декларации; ошибки скрипта и прерванные ячейки представлены статусом. Хранилище `store/load` на сессию, новый изолят на выполнение. [`max_output_tokens`, `yield_time_ms`][codex-runtime] по умолчанию 10 000 токенов и 10 с; `wait` возвращает дельту, может остановить ячейку. Yield не дедлайн. Это отдельный режим от Node REPL. |

Из сравнения важны два различия. Pi и Codex ограничивают **токены модельного результата**, не урезая промежуточные данные скрипта. Pi и Pi Rust также явно говорят, где выход строковый, а где нативный/структурированный. Переносить их рантаймы для этих двух свойств не требуется.

## Замер Jcode

```sh
uv run scripts/codemode_usage.py --workspace /path/to/jcode --end 2026-11-21T05:44:05Z
```

Окно `[14 ноября 05:44:05 UTC, 21 ноября 05:44:05 UTC)`, ровно 7 суток. Только `working_dir` текущего checkout и локальные `session_*.json`/`.journal.jsonl`, чтение без изменений. Рабочие копии других проектов и worktree с другим `working_dir` исключены. Дедупликация снимка и журнала по ID сообщения в сессии, повторов вызовов между сессиями по tool ID. Два повторных сообщения исключены. При чтении живой журнал может быть заменён checkpoint; один проход сообщил об одном таком непрочитанном файле, основные агрегаты совпали в повторных прогонах. Старые уже уплотнённые следы могут быть неполны. Не выгружаются команды, исходники скриптов, тексты ответов, имена сессий, ID и ошибки из логов.

**Ход** здесь означает сохранённый ответ модели с текстом, вызовом или provider-native блоком, не пользовательский запрос и не запись только с reasoning. **Токены** относятся только к записанному коду/видимому тексту результата, `tiktoken 0.14.0` с `o200k_base`. Это общий прокси для разных провайдеров, не счётчик биллинга, повторных чтений контекста или prefix cache. p90 вычислен методом nearest rank.

Это частота синтаксиса, не фактических вызовов и не доказательство спроса на REPL или на массовую подгрузку схем.

### Где могли выиграть, но не вызвали Code Mode

| Кандидаты | Наблюдение | Контрфактуал |
| --- | --- | --- |
| 5+ последовательных отдельных read-only tool-ходов | **9 цепочек** в **8 сессиях**, 56 ходов, 46 125 токенов промежуточных результатов. Например, повторяющийся `read × 5` или `agentgrep → read → agentgrep → read → agentgrep`. | Одно выполнение на цепочку убрало бы до **47** ответов модели, только если все решения между шагами заранее выразимы кодом. При фильтрации 50/75/90% промежуточного вывода условно **21 582 / 33 114 / 40 032** токена чистой экономии. |
| Из них с признаком зависимости | **4 цепочки** в **4 сессиях**, 28 ходов и 34 315 промежуточных токенов. | До **24** ответов и условные **16 438 / 25 016 / 30 164** токена при тех же сценариях. Это подмножество, его не складываем с предыдущей строкой. |
| `bash`-циклы | Из 9 175 вызовов `bash`, 925 сигналов `for … in`/`while read`/`xargs` в 66 сессиях. 70 вызовов в 27 сессиях похожи на чтение/поиск без build/Git/записи; всего 41 048 токенов вывода, медиана 294, p90 1 180. | **0** дополнительных ходов для экономии: shell уже собрал их в одном вызове. Если сохранить только половину вывода, потолок **20 524** токена **до** цены переписывания; ту же фильтрацию умеет сам shell. Считать эти токены потерь Code Mode нельзя. |

Фильтр цепочек строже, чем просто «пять упоминаний инструмента»: максимальная серия одиночных успешных `read`, `agentgrep`, поисковых или подходящих по имени read-only MCP-вызовов; предыдущий результат должен прийти до следующего запроса модели. Новый пользовательский текст, другой инструмент или параллельный ход разрывает серию. Лексическая связь: строка длиной 8+ в следующих аргументах была в предыдущем выводе, но не в предыдущих аргументах. Это может быть общий путь, а подлинная смысловая зависимость может не обнаружиться. Число кандидатов не оценивает скрытые/разрозненные цепочки, а часть совпадений лучше обслужит `batch`. Для прикидки сохраняем конечный результат и стоимость аргументов, вычитаем 20 токенов на шаг и 40 на скрипт (условные JS/receipt накладные расходы), модельный reasoning и кеш не учитываем. Исполнение альтернативного скрипта не наблюдалось.

## Что менять, в порядке выгоды

1. **Бюджет ответа скрипта, не промежуточных данных.** 313 из 955 отчётов в 55 сессиях больше 4 000 токенов. Сумма превышений **1 015 281** токен, валовый потолок без учёта потери фактов и дополнительных запросов. При 2 000 это 487 запусков в 57 сессиях и 1 800 340 токенов, при 8 000 это 91 в 47 и 271 438. Взять опциональный `max_output_tokens` у Pi/Codex. Начать с opt-in на задаче «найти и кратко вернуть», сохранить заголовок ошибки, итог статусов и путь к полному артефакту вне среза. Не вводить глобальный кап без замера: доказательства и большой выход иногда нужны целиком. **Оценка: 1–2 дня.** Прогнать минимум 20 пар одинаковых задач (крупный вывод, намеренно полный текст, ошибка после частичного успеха). Критерий: ниже p90 входных токенов следующего запроса без ухудшения точности и роста повторных запросов за вырезанным текстом. Считать все ходы до решения, а не только первый обрезанный ответ.
2. **Коротко показывать контракт проблемного host-вызова, не печатать весь каталог.** 23 ошибки аргументов, в основном форма запроса `agentgrep`, а не дефицит JS. Взять у Pi точечную подсказку о типе результата и у стороннего харнесса правило исправлять только сбойный шаг. Начать с двух вещей: в ошибке `agentgrep` на вложенном вызове показать исправляемый параметр и один пример, а в кратком справочнике явно развести текст, JSON и структурированный MCP. Если наблюдения подтвердятся на MCP, предложить неразрушающий `result`/preview со стабильной оболочкой, а не менять тип всех `tools.*`. Не повторять автоматически побочные вызовы. **Оценка: 0,5–1 день для подсказок.** На наборе корректных и неверных read/grep-запросов проверить первый удачный результат, число повторов и отсутствие повторного выполнения успешных шагов. Условие продолжения: падает доля ошибок/повторов при сопоставимом составе вызовов.
3. **Только лёгкий эксперимент со steering.** В [Tool calls](../../crates/jcode-base/src/prompt.rs#L47-L56) заменить абстрактное «5+» конкретной поисковой связкой: «найди файлы → прочти окна вокруг совпадений → верни короткий список с путями и строками». Взять у Pi `Promise.allSettled` как пример частично успешного независимого поиска; оставить `batch` для полных независимых результатов, `bash` для shell. Девять кандидатов, включая четыре с лексическим признаком зависимости, дают слабее основание, чем длинные отчёты. **Оценка: до полудня.** A/B на цепочках, одном чтении и настоящем shell-цикле. Оставить подсказку только при сокращении ходов/токенов с тем же набором подтверждённых фактов и без миграции простых вызовов в JS.

**Пока не окупается:** обязательный `CodeModeOnly`, предварительная загрузка всех TypeScript-деклараций, перенос Python/Bun/Node REPL, сохранение всей VM между вызовами, увеличение heap или аналог `exec`/`wait`. Замер показал длинные ответы, но не выявил нехватки времени, памяти или инструментов. Выборка слабо говорит о поиске по большим MCP-каталогам: встроенные функции поиска и справки упомянуты всего в трёх скриптах.
