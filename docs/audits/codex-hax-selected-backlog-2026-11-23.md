# Что забираем из Codex CLI и Hax

Выбор после Ask, 23 ноября 2026 года (AEDT). Подробности и ссылки на исходники: [аудит Codex CLI](codex-cli-parity-2026-11-23.md) и [концепты Hax](hax-concepts-for-jcode-2026-11-23.md). Это очередь работ, не статус реализации.

## Из Codex CLI

1. **CLI для CI.** Добавить к `jcode run` stdin, отдельный файл для финального ответа и режим без сохранения сессии. Сохранить существующие `--json` и `--ndjson`. JSON Schema рассматривать после базового контракта.
2. **Ревью по Git.** Явные цели `--base`, `--commit`, `--uncommitted`; находки с путём, диапазоном строк и серьёзностью. Оставить текущий `/review` для проверки недавней работы сессии.
3. **Worktree и Git diff.** Запуск или fork сессии в отдельном worktree без автоматического удаления. Просмотр Git diff в TUI со staged, unstaged, untracked и ручными правками, а не только патчами агента. Две отдельные части одной области, их можно выпускать независимо.

## Из Hax: в бэклог

**Терминальный e2e.** Синтетический provider → настоящий daemon → TUI в PTY → видимый экран. Первый сценарий: resize во время стрима, отмена и следующий ход без дублей и поздних дельт. Использовать существующие fixtures и изолированный test home, не переносить harness Hax целиком.

Sandbox исключён из этого набора. Остальные идеи остаются в аудитах, без решения об реализации.
