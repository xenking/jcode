# Express token comparison

This compares complete `applet` mount argument objects for the two supported Express macros. The native view is generated by calling the production `jcode_applet_types::compile_express`, not a handwritten reconstruction. Each pair has the same action and intent, and its native view is exactly the view compiled from that pair's Express source. English and Russian are separate, translated fixtures. ReviewChange's built-in labels remain English because that is what the compiler produces.

Both objects are recursively sorted by key and serialized as compact JSON with literal Unicode by `JSON.stringify`. The counts use `cl100k_base` from `js-tiktoken` 1.0.21, not bytes. Savings are native minus Express, divided by native for the percentage. Results on base `02375f71fe851b65cabe21c6ed61da65bf174ee6`:

| Macro | Language | Native | Express | Saved | Saved % |
| --- | --- | ---: | ---: | ---: | ---: |
| GreetingButton | English | 52 | 31 | 21 | 40.4% |
| GreetingButton | Russian | 64 | 43 | 21 | 32.8% |
| ReviewChange | English | 159 | 32 | 127 | 79.9% |
| ReviewChange | Russian | 170 | 43 | 127 | 74.7% |

## Reproduce

From the repository root, with Bun, Rust and justrust installed:

```sh
(cd crates/jcode-applet-types/examples/token-comparison && bun install --frozen-lockfile)
justrust run --local='generate local benchmark data' -p jcode-applet-types --example token_comparison | bun crates/jcode-applet-types/examples/token-comparison/compare.mjs
```

The first install may require network access. Once Bun's locked dependencies and the Rust toolchain and Cargo dependencies are available locally, the comparison itself is offline and makes no API calls. No dependency is added to Jcode runtime.

This measures only these four argument objects, not the system prompt, tool schema, instructions needed to teach Express, provider framing, model output or round trips. Different tokenizers, JSON serialization, inputs, native representations or provider accounting will yield different totals. In particular this is not a claim about end-to-end token or cost savings.
